# 2026-07-27 全栈偏前端每日面试题

## 1. JavaScript：闭包、模块单例与意外内存滞留

- 题型：原理 + 排障
- 难度：中等
- 可能来源或考察方向：[MDN Closures](https://developer.mozilla.org/docs/Web/JavaScript/Guide/Closures)
- 题目：一个页面级模块导出 `register()`，每次调用都把包含 DOM 节点和大响应对象的回调放入模块数组；路由离开后内存不回落。闭包为什么会保留外层变量？如何用 Heap Snapshot 的 retaining path 定位引用链？给出不依赖“手动 GC”的解除订阅与数据截断方案。

## 2. TypeScript：递归条件类型的深度限制与可维护性

- 题型：类型设计 + 工程实践
- 难度：较难
- 可能来源或考察方向：[TypeScript Conditional Types](https://www.typescriptlang.org/docs/handbook/2/conditional-types.html)
- 题目：请设计 `DeepReadonly<T>`，使对象和数组递归只读，但函数保持原类型。大型 DTO 使用后出现 “Type instantiation is excessively deep”。递归类型为何会触发编译器限制？如何通过深度计数、减少分发条件类型或在边界处停止展开，兼顾类型收益和编译性能？

## 3. Promise：`Promise.all` 失败语义与并行任务的补偿

- 题型：原理 + 场景设计
- 难度：中等
- 可能来源或考察方向：[MDN Promise.all](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Promise/all)
- 题目：提交订单时要并行执行库存预占、优惠试算和风控预检。`Promise.all` 任一 reject 后立即 reject，是否代表其余任务已经停止？如何收集已完成任务、向可补偿的后端发起撤销，并避免未处理 rejection？什么时候应使用 `allSettled`，什么时候应该让服务端以一个事务/编排接口承接？

## 4. 浏览器：PerformanceObserver 的 RUM 指标采集与噪声控制

- 题型：性能工程 + 场景
- 难度：较难
- 可能来源或考察方向：[MDN PerformanceObserver](https://developer.mozilla.org/docs/Web/API/PerformanceObserver)
- 题目：为后台系统建立真实用户性能（RUM）采集，怎样通过 `PerformanceObserver` 采集 LCP、CLS、INP 和长任务，并把路由、构建版本、设备档位关联到同一上报？SPA 路由、页面隐藏、采样、上报失败和用户隐私分别怎样处理，才能避免“指标很好但用户仍卡”的误判？

## 5. 网络：OAuth 2.1 Authorization Code + PKCE 与 BFF 边界

- 题型：认证设计 + 安全
- 难度：较难
- 可能来源或考察方向：[OAuth 2.1 draft](https://datatracker.ietf.org/doc/draft-ietf-oauth-v2-1/)
- 题目：React SPA 接入企业 SSO，如何说明 Authorization Code + PKCE 中 `state`、`nonce`、`code_verifier` / `code_challenge` 分别防什么？若改为 BFF，浏览器、BFF、授权服务器各保存什么，token 如何避免暴露给 JS？登录回调、跨站 Cookie、登出和多标签页过期应如何设计？

## 6. React：列表 `key` 与状态保留/重置的精确语义

- 题型：原理 + 排障
- 难度：中等
