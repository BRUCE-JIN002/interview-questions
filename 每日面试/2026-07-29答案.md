# 2026-07-29 全栈偏前端每日面试参考答案

## 1. JavaScript：私有字段、品牌检查与跨实例访问

### 参考答案

`#token` 由语言层私有槽保存，不能通过属性枚举、字符串键或代理伪造；`_token` 只是约定，闭包可私有但不天然属于实例。类定义中的方法具有该私有名称的访问权，所以可读取同类另一实例的 `#token`；子类和外部对象没有此权限。`#token in value` 是品牌检查，可先判断对象是否属于具备该私有槽的实例。它防的是误访问，不是密钥管理：运行中的 JS 仍可使用值，真正的密钥应尽量不下发浏览器并由服务端保管。

### 关键考点

私有槽、品牌检查、封装与安全边界。

### 常见追问或变体

私有字段不能被 `structuredClone` 保留；序列化 DTO 时应显式挑选公开字段。

## 2. TypeScript：`NoInfer` 与泛型 API 的推断控制

### 参考答案

```ts
function createColorPicker<C extends string>(
  colors: readonly C[],
  defaultColor?: NoInfer<C>,
) {
  return { colors, defaultColor };
}

const colors = ['red', 'blue'] as const;
createColorPicker(colors, 'red');
// createColorPicker(colors, 'green'); // 类型错误
```

`NoInfer<C>` 阻止第二个参数成为 `C` 的推断来源，先由 `colors` 确定联合类型。`as const` 保留字面量，`satisfies` 检查结构同时尽量保留窄类型；它们都不替代运行时校验。URL 输入应与允许集合比对，非法值回退默认值或报 400。

### 关键考点

泛型推断来源、字面量类型、编译期与运行期边界。

### 常见追问或变体

旧版本 TypeScript 可用 `NoInfer` polyfill，但应升级或验证其推断行为，避免复杂条件类型掩盖 API 设计问题。

## 3. ES6+：标准 Decorators 的执行顺序与初始化器

### 参考答案

装饰器接收被装饰的值和 `context`（含 kind、name、static、private、`addInitializer` 等）；方法装饰器通常返回替换方法，字段装饰器可返回初始化转换函数。表达式先按书写顺序求值，装饰器应用顺序与层叠调用相反。`addInitializer` 可在实例创建时绑定方法、注册实例资源，避免在装饰时访问实例。标准 Decorators 与 TypeScript 旧 `experimentalDecorators` 的签名和 metadata 机制不同，不能不经验证就迁移 NestJS DI。

### 关键考点

提案语义、求值/调用顺序、初始化时机、生态兼容性。

### 常见追问或变体

装饰器适合声明性横切能力；权限和输入校验仍必须在可测试的运行时边界执行。

## 4. 异步调度：`scheduler.postTask`、优先级与取消

### 参考答案

输入的状态更新应同步且轻量；过滤任务使用 `user-visible` 并按批次让出；预取使用 `background`。用 `TaskController` 的 signal 取消过时过滤和预取。`postTask` 表达任务优先级，微任务会在任务间清空且滥用会饿死渲染，`requestAnimationFrame` 适合下一帧视觉更新，`setTimeout` 没有语义优先级。降级时用 `setTimeout`/`MessageChannel` 分块，每块检查取消和时间预算。

### 关键考点

任务优先级、协作式切片、取消、渲染机会。

### 常见追问或变体

本地计算极大时应考虑 Worker；调度不能使 CPU 工作本身消失。

## 5. 浏览器：Shadow DOM 的事件传播与组件事件契约

### 参考答案

事件跨 shadow boundary 时会发生 retargeting，外部监听者看到的 target 往往是宿主；需要真实路径时读 `composedPath()`。原生 click 通常可组合传播；自定义公共事件应显式 `bubbles: true, composed: true`，并在 `detail` 中给出稳定、最小化的数据。内部焦点管理、临时 hover、实现细节事件保持不组合，避免组件内部成为外部耦合面。

### 关键考点

封装边界、事件重定向、公共事件契约。

### 常见追问或变体

不要让外部依赖 `composedPath()` 的内部节点；组件升级会轻易破坏这种依赖。

## 6. 网络安全：HSTS、CSP 与前端第三方脚本治理

### 参考答案

全站 HTTPS 后设置 HSTS（确认子域均支持时再 `includeSubDomains`/preload）。CSP 以 nonce 标记本响应允许的内联脚本；`strict-dynamic` 让受 nonce 信任的加载器按策略扩展信任，hash 适合内容固定的内联片段，第三方域需最小 allowlist。先以 Report-Only 收集违例，再修复后 enforce。首次 HTTP 请求还没拿到 HSTS，故需重定向和预加载；CSP 是缓解层，编码、消毒、Cookie/权限控制仍不可省。

### 关键考点

纵深防御、脚本来源、灰度、首次访问风险。

### 常见追问或变体

第三方脚本应有所有者、用途、版本与下线机制；不要因一处违例加入宽泛 `unsafe-inline`。

## 7. React：React Compiler 与手写 memo 的取舍

### 参考答案

Compiler 可自动缓存符合规则的组件和 Hook 中重复计算/JSX 创建，减少由父级更新导致的无意义工作；前提是渲染纯粹、Hook 规则正确且不修改外部可变值。先启用 React ESLint 规则，结合 Profiler 找真实热点，再在少量页面开启并比较交互延迟、渲染次数和异常率。依赖对象身份的隐式协议、渲染副作用和违规 Hook 会破坏假设。手写 memo 仍适合已测得的热点、跨非编译代码边界或必须稳定引用的外部订阅 API。

### 关键考点

纯渲染、自动记忆化、性能测量、渐进发布。

### 常见追问或变体

不要把所有 `useMemo` 删除；迁移前后以行为和 profile 数据而非“代码更少”作为判断依据。

## 8. Vue 3：`useId`、SSR 与可访问表单关联

### 参考答案

随机数和请求间共享计数器会让服务端 HTML 与客户端首次渲染 id 不一致，导致 hydration 警告和 ARIA 关联错位。`useId()` 生成可在 SSR/客户端对应的应用内 id；同一字段派生 `-error` 等后缀即可关联。循环项用稳定业务 key，条件分支须保证服务端和客户端初始条件一致；多应用实例依赖各自 app 的配置/前缀，避免把 id 当全局业务主键。

### 关键考点

hydration 确定性、可访问性关联、列表 key、多应用隔离。

### 常见追问或变体

若初始数据仅客户端可得，应让该区域延后挂载或传入服务端确定的初始状态。

## 9. 算法：柱状图中的最大矩形

### 参考答案

栈保存递增高度的下标；遇到更低柱时，被弹出的柱子右边界已确定为当前位置前一格，左边界是弹栈后的栈顶后一格。两端补 0 可统一结算。

```ts
function largestRectangleArea(heights: number[]) {
  const a = [0, ...heights, 0];
  const stack: number[] = [];
  let best = 0;
  for (let i = 0; i < a.length; i++) {
    while (stack.length && a[stack.at(-1)!] > a[i]) {
      const h = a[stack.pop()!];
      const left = stack.length ? stack.at(-1)! : -1;
      best = Math.max(best, h * (i - left - 1));
    }
    stack.push(i);
  }
  return best;
}
```

时间 O(n)、空间 O(n)。`>` 让等高柱保留到右侧统一结算；`>=` 会更早替换下标，也正确但边界归属不同。

### 关键考点

单调栈、左右第一个更小元素、哨兵、不变量。

### 常见追问或变体

最大矩形在 0/1 矩阵中可逐行累计高度后复用本算法。

## 10. Next.js：动态 CSP nonce 与静态优化的边界

### 参考答案

nonce 必须每次响应不同，通常在 `proxy` 生成，写入 CSP 响应头并通过请求头让页面读取后标到必要脚本。按请求生成 nonce 会使该响应动态化，不能直接享受纯静态 HTML 的共享缓存，也会限制 ISR/PPR 的可复用方式。公开营销页优先用无内联脚本的 hash/严格外部脚本策略以保留静态/CDN 缓存；登录后页可使用动态 nonce 和私有缓存。不要让用户相关响应进入共享 CDN 缓存。

### 关键考点

nonce 唯一性、动态渲染、缓存范围、安全与性能取舍。

### 常见追问或变体

nonce 不是 XSS 修复；任何把不可信字符串拼成可执行脚本的代码仍须消除。

## 11. Node.js：优雅关闭中的 Keep-Alive 与滚动发布

### 参考答案

收到 SIGTERM 后先标记 not-ready/从负载均衡摘流，再 `server.close()` 停止接收新连接；等待在途请求，在截止时间前让上游 fetch 共享 abort signal，随后关闭空闲连接并终止逾期连接，最后释放 DB/队列资源退出。立即 `process.exit()` 会截断响应、日志和事务。观测 ready 到退出的在途数、关闭耗时、强杀数、P95/P99、5xx 与上游 abort 比例，并在预发布演练。

### 关键考点

摘流、连接排空、截止时间、级联取消、发布可观测性。

### 常见追问或变体

WebSocket/SSE 需要单独通知重连并设更明确的排空策略。

## 12. NestJS：Guard、Interceptor、Pipe 与 Exception Filter 的职责边界

### 参考答案

Guard 做身份和授权判定；Pipe 做 DTO 转换/校验；Interceptor 包裹执行以计时、脱敏和审计成功结果；Exception Filter 统一映射未处理异常及失败响应。body 内资源 id 先经 DTO 校验，在 Guard 或专用授权服务中从可信 request body 读取并查资源归属，不能相信客户端声称的 owner。审计可由 Interceptor 记录成功，在 Filter 记录失败并共享 request id。Controller 保持协议编排，不用散落 `try/catch` 吞没错误。

### 关键考点

请求生命周期、资源级授权、横切关注点、统一错误契约。

### 常见追问或变体

审计写入失败不得改变主请求语义时，应异步投递并监控补偿队列。

## 13. 数据库/接口：软删除、唯一约束与“恢复”语义

### 参考答案

若删除后仍占用 slug，可对 `slug` 做普通唯一约束；若只要求活跃记录唯一，PostgreSQL 可用 `CREATE UNIQUE INDEX ... ON projects(slug) WHERE deleted_at IS NULL`。创建、删除、恢复都交给数据库约束和事务处理，冲突返回明确 409；应用层“先查”不足以消除竞态。slug 可复用时，旧链接应有不可复用的稳定 id/历史重定向策略，审计保留原记录；恢复时若 slug 已被占用，应要求改名或拒绝恢复，不能静默覆盖。

### 关键考点

部分唯一索引、事实约束、并发冲突、恢复产品语义。

### 常见追问或变体

多租户通常把 tenant_id 纳入唯一索引；删除和恢复 API 都应幂等并携带版本/更新时间以处理并发编辑。

## 14. AI 前端：流式多模态上传的进度、取消与内容安全

### 参考答案

状态机可分为 `selected → uploading → processing → streaming → completed/failed/cancelled`，工具卡再有 pending/succeeded/failed。取消上传中止传输并清理临时会话；取消生成 abort 流但保留已确认文件和已生成片段，并向服务端发送 run cancel；断线重连用 run/message id 拉取游标后续或最终快照，不能盲目重发工具调用。预览、引用和工具卡显示文件来源、扫描/解析状态和权限；文件内容作为不可信数据传入模型，不渲染为指令。

### 关键考点

显式状态机、分层取消、幂等恢复、来源与信任显示。

### 常见追问或变体

服务端应限制文件类型/大小、病毒扫描、租户隔离和短期下载 URL；前端进度不能作为处理完成的唯一事实源。

## 15. Agent/MCP：第三方 MCP Server 的准入、授权与隔离

### 参考答案

建立受审计的 server 注册表，固定身份/端点/版本，按 server、工具和资源分别 allowlist；OAuth 使用每用户、最小 scope、可撤销短期令牌。工具描述、返回文本、URL 皆为不可信内容，只能作为数据输入，调用前由服务端重新做 schema、权限、租户和风险校验。写操作展示实际工具、参数摘要与影响范围，用户确认后签发短时且绑定参数的授权票据；记录用户、scope、server、请求、确认、结果和关联 id。scope 异常扩大、可疑重定向或注入命中时拒绝调用、撤销会话并告警。

### 关键考点

供应链准入、最小权限、不可信工具内容、确认绑定、审计与撤销。

### 常见追问或变体

不能仅靠模型“承诺不调用危险工具”；策略必须在模型外、服务端可执行。
