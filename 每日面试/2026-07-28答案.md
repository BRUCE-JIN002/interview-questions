# 2026-07-28 全栈偏前端每日面试参考答案

## 1. JavaScript：`Set` 组合方法的集合语义与性能边界

**参考答案：**`intersection` 求共同权限，`difference` 求当前角色可授予但用户尚未拥有的权限，`union` 合并来源，`isSubsetOf` 可校验请求权限是否全部允许。Set 按 SameValueZero 比较；对象按引用身份，不会深比较。把数组转换为 Set 应放在数据变化的缓存/selector 中，而不是每次渲染都做；数万项还需避免把结果反复转回数组。

**关键考点：**集合代数、对象身份、渲染期计算成本。

**常见追问或变体：**权限对象应以稳定 id 建 Set；不同对象实例但同 id 时不能直接放对象。

## 2. TypeScript：模板字面量类型与类型安全的路由参数

**参考答案：**按 `/` 分段，遇到 `:${infer Name}` 就把 Name 合并进结果。

```ts
type SegmentParam<S extends string> = S extends `:${infer K}` ? { [P in K]: string } : {};
type Params<Path extends string> =
  Path extends `${infer Head}/${infer Tail}`
    ? SegmentParam<Head> & Params<Tail>
    : SegmentParam<Path>;

type P = Params<'/teams/:teamId/members/:memberId'>;
// { teamId: string } & { memberId: string }
```

它依赖 `as const` 保留路径字面量；运行时仍要解析 URL、校验缺失/重复参数和编码。复杂的可选段、正则段或巨大联合应简化成显式参数类型，避免递归类型拖慢语言服务。

**关键考点：**模板字面量推断、交叉类型累积、编译期与运行期边界。

**常见追问或变体：**前导 `/` 产生的空段会映射为 `{}`，不影响结果。

## 3. Promise：`Promise.withResolvers()`、外部 resolve 与状态所有权

**参考答案：**它返回 `{ promise, resolve, reject }`，把 Promise capability 的创建从 executor 中拿出来，适合事件回调驱动的完成时机；并不提供取消或多次 settle。连接管理器应私有化 resolve/reject，并维护单个 `connecting` Promise：首次调用创建它，成功清空连接中状态，失败也清空以便重试；超时、close、open 只由管理器按状态机竞争完成一次。

**关键考点：**Promise 一次 settle、capability、in-flight 去重、状态所有权。

**常见追问或变体：**外部调用者只拿到 `Promise`，不能拿到 resolver；取消需要关闭 socket 或 AbortSignal，而不是 reject 后假装 I/O 已停止。

## 4. 浏览器：BFCache 命中、恢复与页面状态正确性

**参考答案：**BFCache 是浏览器冻结整页内存快照并在返回时恢复；HTTP 缓存复用资源响应，SPA 缓存复用应用数据。`pageshow` 中 `event.persisted` 为真可识别恢复，`pagehide` 可做可恢复的暂停；DevTools 的 Back/forward cache 面板能说明未命中原因。恢复后保留滚动、表单草稿和局部 UI，但应重新校验会话、库存/订单等易变数据。`unload` 会妨碍 BFCache，改用 `pagehide`，并让资源清理可重复。

**关键考点：**页面冻结恢复、状态新鲜度、生命周期事件。

**常见追问或变体：**不要把 `pageshow` 当首次加载；逻辑须同时处理 `persisted === false`。

## 5. 网络：Client Hints、`Vary` 与响应变体缓存

**参考答案：**服务端通过 `Accept-CH` 请求相关 Hint，并按收到的 DPR、Viewport-Width、Save-Data 选择图片变体。凡影响表示的请求头都要进入 `Vary` 和 CDN 缓存键；否则高 DPR 图片可能被低 DPR 用户复用。`Vary: User-Agent` 维度过大，通常比显式、有限的 Hint 更易击穿缓存。缺少 Hint 时返回保守的默认尺寸/格式，不要猜测并写入一个无区分缓存条目。

**关键考点：**协商、缓存键正确性、命中率与变体维度。

**常见追问或变体：**响应还应设置合理的 `Cache-Control`，不能只依赖 `Vary` 管理时效性。

## 6. React：`useOptimistic` 的回滚、确认与并发提交

**参考答案：**把服务端确认的点赞状态作为 base state；点击时 dispatch 一个带唯一 operation id 的乐观动作，成功后以服务端权威值更新 base，失败则移除/标记该操作。更新函数必须纯粹，因为 React 可重放渲染。乱序响应不能按到达顺序覆盖：应按 operation id 或服务端版本归并。写接口需幂等键；不可安全合并的操作（支付、库存扣减）应禁用重复提交或串行化。

**关键考点：**乐观层与权威层、纯 reducer、乱序响应、幂等。

**常见追问或变体：**网络失败不等于服务端未成功；重试前应查询或复用同一个幂等键。

## 7. Vue 3：`watch` 的暂停/恢复、清理与异步竞态

**参考答案：**`pause()` 临时停止响应变化，`resume()` 恢复，`stop()` 永久释放 watcher；面板卸载时用 stop。每轮回调创建 `AbortController`，通过 cleanup 在下一轮或 stop 时 abort 旧请求。仅有 `loading` 不能区分多个并发请求，旧请求仍可能最后写入状态；还应校验请求序号或 signal 是否已 abort。

**关键考点：**watcher 生命周期、cleanup、取消与结果时序。

**常见追问或变体：**暂停不应替代组件卸载清理；恢复后是否立即重新拉取要由产品语义显式决定。

## 8. 手写：支持超时和取消等待的异步互斥锁

**参考答案：**用队列保存等待者，每个等待者有 settle 状态和清理函数；release 只允许一次，并把锁交给队首仍有效的等待者。

```ts
function createMutex() {
  let locked = false;
  const queue: Array<(release: () => void) => void> = [];
  const grant = () => {
    const next = queue.shift();
    if (next) next(makeRelease()); else locked = false;
  };
  const makeRelease = () => {
    let released = false;
    return () => { if (!released) { released = true; grant(); } };
  };
  return {
    acquire({ signal, timeout = 0 }: { signal?: AbortSignal; timeout?: number } = {}) {
      return new Promise<() => void>((resolve, reject) => {
        let done = false;
        let timer: ReturnType<typeof setTimeout> | undefined;
        const cleanup = () => { if (timer) clearTimeout(timer); signal?.removeEventListener('abort', abort); };
        const abort = () => finish(reject, signal?.reason ?? new DOMException('Aborted', 'AbortError'));
        const finish = (settle: (v: any) => void, value: any) => {
          if (done) return; done = true; cleanup();
          const i = queue.indexOf(waiter); if (i >= 0) queue.splice(i, 1); settle(value);
        };
        const waiter = (release: () => void) => finish(resolve, release);
        if (signal?.aborted) return abort();
        signal?.addEventListener('abort', abort, { once: true });
        if (timeout > 0) timer = setTimeout(() => finish(reject, new Error('Mutex timeout')), timeout);
        if (!locked) { locked = true; waiter(makeRelease()); } else queue.push(waiter);
      });
    }
  };
}
```

布尔值无法保存 FIFO 等待者、取消和所有权。锁只适用于单 JS 进程；跨进程需 Redis/数据库等分布式协调。

**关键考点：**FIFO、队列移除、幂等 release、进程边界。

**常见追问或变体：**持锁代码应使用 `try/finally` 调用 release，否则会永久阻塞。

## 9. 算法：课程依赖的拓扑排序与环检测

**参考答案：**把 `prerequisite -> course` 建边，统计每门课程入度；先把入度为 0 的课程入队。每弹出一门课就减少后继入度，新变为 0 的入队。输出数等于课程数时得到合法序；否则剩余节点互相依赖形成环。

```ts
function findOrder(n: number, prerequisites: number[][]) {
  const graph = Array.from({ length: n }, () => [] as number[]);
  const inDegree = Array(n).fill(0);
  for (const [course, pre] of prerequisites) { graph[pre].push(course); inDegree[course]++; }
  const queue = inDegree.flatMap((d, i) => d === 0 ? [i] : []);
  const order: number[] = [];
  for (let head = 0; head < queue.length; head++) {
    const node = queue[head]; order.push(node);
    for (const next of graph[node]) if (--inDegree[next] === 0) queue.push(next);
  }
  return order.length === n ? order : [];
}
```

时间 O(V+E)，空间 O(V+E)。DFS 的 visiting/visited 三色状态中，访问到 visiting 节点即发现回边。

**关键考点：**有向图建边方向、入度、拓扑序、环。

**常见追问或变体：**若需字典序最小结果，用优先队列替代普通队列。

## 10. Next.js：`proxy` 层的鉴权边界与重定向安全

**参考答案：**`proxy` 可快速读取已验证会话线索、按路径做粗粒度拦截、设置重定向和安全头；它不是数据访问的授权替代。Route Handler、Server Action 和数据库查询仍须以可信身份做资源级授权。`next` 只接受站内相对路径或经过 allowlist 解析后的 URL，拒绝 `//evil.example`、绝对 URL 和编码绕过。避免在 proxy 中访问慢数据库：它处于请求路径前段，额外延迟会放大。

**关键考点：**纵深防御、开放重定向、边缘路径延迟。

**常见追问或变体：**客户端隐藏菜单仅改善体验，不能作为权限控制。

## 11. Node.js：`diagnostics_channel` 与低侵入请求诊断

**参考答案：**发布者向命名 channel `publish` 诊断消息，订阅者 `subscribe` 消费；无订阅时可避免大部分额外工作。适配层可从 AsyncLocalStorage 取 request id，记录目标、耗时、状态码和错误分类；日志只保留脱敏摘要、白名单字段和 hash，永不写凭据或完整请求体。订阅回调在运行时路径中执行，必须轻量、非阻塞并把重处理异步投递。

**关键考点：**发布订阅、上下文关联、数据最小化、观测开销。

**常见追问或变体：**诊断数据格式应版本化，避免订阅方与发布方隐式耦合。

## 12. NestJS：请求内事务边界与异步副作用

**参考答案：**Controller 只负责协议适配，Service 编排用例，Repository 封装持久化；Interceptor 不应偷偷包住所有请求事务，因为读接口、流式响应和长请求的语义不同。由用例服务显式开启 transaction，将 transaction-scoped repository/context 传给订单、库存和审计写入。提交前不能发通知，否则回滚会产生幽灵消息；同一事务写 outbox，独立 worker 在提交后幂等投递并记录状态。

**关键考点：**显式事务范围、原子写入、outbox、最终投递。

**常见追问或变体：**外部支付不能纳入本地事务，需幂等外部调用和补偿/Saga。

## 13. 缓存设计：Cache-Aside 的失效、穿透与一致性取舍

**参考答案：**读路径先读缓存，miss 时读库并以短 TTL 回填；更新先写数据库成功，再删除缓存，后续读取回填新值。删除失败需要重试/消息补偿；并发读回填旧值可用版本号、短 TTL 或延迟双删等按一致性需求取舍。热点失效用 singleflight/互斥重建和 TTL 抖动；不存在 id 用短 TTL 空值或布隆过滤器防穿透。先更新缓存再更新库会出现数据库失败或并发覆盖，缓存与事实源更难收敛。

**关键考点：**事实源、失效顺序、击穿/穿透、版本与 TTL。

**常见追问或变体：**强一致库存不要只依赖缓存，扣减必须在数据库或专用库存系统原子执行。

## 14. AI/RAG：提示注入下的检索内容与工具调用隔离

**参考答案：**检索文本是数据，不是高优先级指令；把来源、租户、权限和信任等级随 chunk 一起传递，并对其中的“指令”标识为不可信。模型提出工具调用后，服务端以 schema、allowlist、当前用户权限、资源范围和风险策略重新校验；高风险调用还须绑定参数的用户确认令牌。前端引用卡展示来源、摘录、权限范围与不可信提示，确认页展示实际工具、参数和影响范围，不能把文档中的话渲染成系统命令。

**关键考点：**数据/指令分离、服务端策略执行、来源可见性、确认绑定。

**常见追问或变体：**过滤关键词不足以防注入；必须假定绕过文本会进入上下文。

## 15. Agent：离线评测、线上反馈与安全发布门禁

**参考答案：**数据集应覆盖常规问答、歧义/缺资料、长上下文、注入、越权、工具超时和错误工具结果，并按版本冻结且与调参集隔离。用人工标注或可审计规则评估任务完成、引用正确性和安全拒答；同时量化工具成功率、P95 延迟、token/成本。线上先小流量灰度，记录匿名任务类别、纠正/转人工、失败和安全事件；超过预设的质量下降、安全失败或成本阈值自动暂停并回滚。评测集需要持续补充线上代表性失败样本，但新样本应进入后续独立评估轮次。

**关键考点：**训练/评测隔离、多指标权衡、灰度、可执行回滚。

**常见追问或变体：**LLM-as-a-judge 应用校准样本和人工抽检，不能把单一模型评分当真实用户满意度。
