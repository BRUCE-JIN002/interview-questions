# 2026-07-30 全栈偏前端每日面试题

## 1. JavaScript：用 `WeakMap` 保存实例元数据的边界

- 题型：JavaScript 原理 + 代码设计
- 难度：中等
- 可能来源或考察方向：[MDN WeakMap](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/WeakMap)
- 题目：一个埋点 SDK 要为 DOM 节点和第三方对象保存初始化状态、订阅清理函数和请求上下文，但不能修改对象本身。为什么 `WeakMap` 比普通 `Map` 更适合？它如何避免“因缓存键而保活”的问题？为什么不能枚举它的键，如何设计批量清理、调试与显式 `dispose()`？

## 2. TypeScript：`noUncheckedIndexedAccess` 与边界数据建模

- 题型：TypeScript + 工程实践
- 难度：中等
- 可能来源或考察方向：[TypeScript noUncheckedIndexedAccess](https://www.typescriptlang.org/tsconfig/noUncheckedIndexedAccess.html)
- 题目：开启 `noUncheckedIndexedAccess` 后，`Record<string, User>[id]` 的类型变成 `User | undefined`，许多旧代码报错。它修复了什么真实缺陷？如何分别为“可能缺失的缓存”“必填且已校验的配置”“数组按下标访问”建模，避免到处滥用非空断言 `!`？迁移时怎样分层推进？

## 3. Promise：`Promise.race` 超时封装为什么常常泄漏工作

- 题型：异步原理 + 手写点评
- 难度：较难
- 可能来源或考察方向：[MDN Promise.race](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Promise/race)、综合整理
- 题目：请点评 `Promise.race([fetch(url), timeout(3000)])` 实现超时的缺陷：超时后原请求、定时器和可能出现的 rejection 分别怎样处理？设计一个接受 `AbortSignal` 的请求包装约定，使调用方能区分超时、用户取消和网络失败；为什么包装层不能凭空取消任意 Promise？

## 4. 浏览器：Popover API、top layer 与焦点管理

- 题型：浏览器平台 + 可访问性
- 难度：中等
- 可能来源或考察方向：[MDN Popover API](https://developer.mozilla.org/docs/Web/API/Popover_API)
- 题目：通知中心、筛选菜单和确认框都使用浮层。说明 Popover API 的 `auto` 与 `manual` 模式、top layer、light dismiss 与 `beforetoggle`/`toggle` 事件；它与 `dialog` 的模态语义和焦点要求有何区别？在 React/Vue 中应如何把“开关状态”与浏览器实际关闭事件同步，避免 ESC 或点击外部后 UI 状态失真？

## 5. 网络安全：Fetch Metadata 作为 CSRF 的纵深防御

- 题型：网络安全 + 接口设计
- 难度：较难
- 可能来源或考察方向：[OWASP CSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)
- 题目：Cookie 登录的 BFF 要保护转账、改邮箱等写接口。`Sec-Fetch-Site`、`Sec-Fetch-Mode`、`Sec-Fetch-Dest` 可怎样作为服务端拒绝明显 cross-site 写请求的信号？它与 SameSite Cookie、Origin/Referer 校验、CSRF token 各解决什么问题？哪些旧浏览器、同站跨子域和 WebView 情况要求安全降级，不能只依赖 Fetch Metadata？

## 6. React：`useImperativeHandle` 的最小命令式 API

- 题型：React 组件设计 + 项目经验
- 难度：中等
- 可能来源或考察方向：[React useImperativeHandle](https://react.dev/reference/react/useImperativeHandle)
- 题目：一个可复用的文件上传组件需要暴露 `openPicker()`、`focus()`、`clear()`，同时仍支持受控 `value` 与异步上传。如何用 `ref`/`useImperativeHandle` 只暴露稳定、最小的命令式能力？为什么不应把内部 DOM、请求实例或任意 state 直接暴露？在 React 严格模式和组件卸载后的异步回调中怎样避免失效调用？

## 7. Vue 3：泛型组件与具名插槽的类型契约

- 难度：较难

- 题目：设计一个 `DataTable<T>`：调用方传入 `rows: T[]`、行 key 和列定义，并通过 `#cell` 插槽渲染单元格。如何让列字段、插槽参数和事件 payload 尽量保持类型关联？运行时为何仍必须校验后端数据和列配置？若类型过于复杂影响模板可读性，怎样在类型精度与组件可维护性之间取舍？

## 8. 手写：实现可取消的异步互斥锁

- 题型：手写实现 + 并发控制
- 难度：较难
- 可能来源或考察方向：综合整理
- 题目：实现 `acquire(signal?): Promise<() => void>`：未被占用时立即获得释放函数；被占用时按 FIFO 排队；等待期间取消应从队列移除并拒绝；`release` 必须幂等，且不能让一个等待者的取消阻塞后续等待者。说明状态、时间/空间复杂度，以及为何业务逻辑不应长期持锁等待网络请求。
