# 2026-07-27 全栈偏前端每日面试参考答案

## 1. JavaScript：闭包、模块单例与意外内存滞留

**参考答案：**闭包让函数继续引用其创建时的词法环境；模块单例中的数组可达，数组中的回调及其捕获对象也可达，因而不会回收。用 Heap Snapshot 比较前后快照，从大对象沿 retaining path 找到回调数组/事件监听器。路由卸载时执行 unsubscribe，数组中删除回调；回调只捕获 id 或必要字段，不捕获 DOM 和整份响应。

**关键考点：**可达性而非“闭包必泄漏”、模块生命周期、retaining path。

**常见追问或变体：**`WeakMap` 只能弱持有键，不能替代显式取消订阅。

## 2. TypeScript：递归条件类型的深度限制与可维护性

**参考答案：**函数不应递归映射；对象映射属性、数组映射元素即可。

```ts
type DeepReadonly<T> = T extends (...args: any[]) => any ? T
  : T extends readonly (infer U)[] ? readonly DeepReadonly<U>[]
  : T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
  : T;
```

深层/联合类型会在条件类型分发时指数展开。可传递元组深度计数，达到边界返回 `Readonly<T>`；避免对大联合重复递归，公开 API 只暴露必要层级。类型工具不应拖慢编辑器和构建。

**关键考点：**条件类型分发、递归终止、编译性能。

**常见追问或变体：**`Date`、`Map` 等实例通常应视为原子类型或单独约定转换规则。

## 3. Promise：`Promise.all` 失败语义与并行任务的补偿

**参考答案：**`Promise.all` 不会取消已经开始的 Promise；它只是尽早向调用方 reject，其余任务仍可能完成。为每项操作保存结果和可取消句柄，失败时 await 已启动任务的收敛结果，再对成功的、可逆操作执行补偿，并统一消费 rejection。需要展示每项结果时用 `allSettled`；强一致业务让服务端事务或 Saga 编排，前端不能可靠充当事务协调者。

**关键考点：**Promise 不自带取消、失败快返回、补偿不是数据库事务。

**常见追问或变体：**`AbortController` 只能请求支持它的 I/O 停止，不能回滚已提交操作。

## 4. 浏览器：PerformanceObserver 的 RUM 指标采集与噪声控制

**参考答案：**尽早注册 observer，采集 `largest-contentful-paint`、`layout-shift`、`event`/INP 与 `longtask`，页面隐藏时确定最终 LCP；用 navigation id、路由、release、设备和网络类型关联。SPA 要按软导航切分指标，按用户或会话采样并用 `sendBeacon`/keepalive 上报。过滤无用户输入的 CLS，限制文本和 URL 等敏感属性；同时按业务交互分组，避免只看聚合 Web Vitals 掩盖特定按钮的卡顿。

**关键考点：**生命周期、软导航、采样、隐私和业务维度归因。

**常见追问或变体：**observer 回调也在主线程，采集逻辑要轻量且不能每条都立即发网。

## 5. 网络：OAuth 2.1 Authorization Code + PKCE 与 BFF 边界

**参考答案：**`state` 绑定发起和回调以防 CSRF，OIDC 的 `nonce` 绑定 ID Token 以防重放，PKCE 的 verifier/challenge 让被截获的授权码不能单独换 token。BFF 持有 access/refresh token，浏览器只持有 `HttpOnly`、`Secure`、合适 SameSite 的会话 Cookie；BFF 再代用户访问资源服务。回调校验 state/nonce/redirect URI；跨站写操作补 CSRF 防护；登出撤销服务端会话并通知标签页，401 后由 BFF 统一刷新或要求重登。

**关键考点：**授权码拦截、token 不落 JS、Cookie 仍需 CSRF 防护。

**常见追问或变体：**不要把 access token 放 URL、localStorage 或可被任意第三方脚本读取的全局状态。

## 6. React：列表 `key` 与状态保留/重置的精确语义

**参考答案：**React 按组件类型、在树中的位置和 key 识别状态身份。订单切换本质是新实体时，可在 `Form` 上用 `key={orderId}` 使其卸载重建；若要保留草稿，则以 orderId 管理草稿并在切换时显式载入，不能混用。可变列表的 index 会随插入/排序改变，使状态错误迁移到另一行。

**关键考点：**state 绑定渲染树位置、key 是身份不是消除 warning 的字符串。

**常见追问或变体：**随机 key 会导致每次渲染重建，破坏输入和性能。

## 7. Vue 3：SSR hydration 不一致的定位与避免

**参考答案：**先保留服务端响应 HTML，在开发环境对照浏览器警告位置与客户端首次渲染数据。`Date.now()`、`Math.random()`、locale、`window`、客户端缓存、浏览器自动修正的无效嵌套都会使两端树不同。将首屏所需时间/随机种子和数据序列化注入；仅浏览器能力放在 `onMounted`，或使用明确的客户端专属边界。不要用 suppress 类手段掩盖真实差异。

**关键考点：**首次渲染确定性、HTML 解析差异、服务端注入状态。

**常见追问或变体：**服务端和客户端依赖版本不一致也会造成结构或属性差异。

## 8. 手写：可取消的 `debounce`，支持 `flush` 与保留 this/参数

**参考答案：**保存最后的上下文和参数；新调用清除旧 timer。`cancel` 清理 timer 和引用，`flush` 在有等待任务时立刻调用。

```ts
function debounce<T extends (...args: any[]) => any>(fn: T, wait: number) {
  let timer: ReturnType<typeof setTimeout> | undefined;
  let ctx: ThisParameterType<T>; let args: Parameters<T>;
  const invoke = () => { timer = undefined; const result = fn.apply(ctx, args); args = undefined as any; return result; };
  function wrapped(this: ThisParameterType<T>, ...next: Parameters<T>) {
    ctx = this; args = next; if (timer) clearTimeout(timer);
    timer = setTimeout(invoke, wait);
  }
  wrapped.cancel = () => { if (timer) clearTimeout(timer); timer = undefined; args = undefined as any; };
  wrapped.flush = () => timer ? invoke() : undefined;
  return wrapped;
}
```

搜索 debounce 只延后发起；已发出的旧请求仍可能晚到，需 abort 或以请求序号忽略旧结果。

**关键考点：**尾触发、this/参数、取消定时器与取消网络请求不同。

**常见追问或变体：**若要求返回 Promise，要定义多次调用共享哪一次结果，避免悬空 Promise。

## 9. 算法：最小覆盖子串

**参考答案：**用 `need` 保存目标次数，右指针扩张并维护已满足的不同字符数；当所有类别满足时不断收缩左边界并记录最短窗口。每个字符至多进出窗口一次，时间 O(|s| + |t|)，空间 O(字符集)。只用集合会丢失 `AABC` 中 A 的两次需求。

**关键考点：**计数窗口、满足条件后收缩、重复字符。

**常见追问或变体：**字符集大时用 `Map`，ASCII 场景可用数组优化常数。

## 10. Next.js：Cache Components、动态数据与失效策略

**参考答案：**把公开、稳定的商品介绍置于可缓存边界；实时库存和用户价保持动态，并以 Suspense 分隔，避免动态 API 让整个页面失去缓存价值。`use cache` 只能包裹输入明确、无用户私密上下文的计算/读取；更新后按商品或标签失效静态内容，库存按短 TTL/事件失效，用户价的缓存键必须包含可信用户身份或不共享缓存。

**关键考点：**缓存边界、动态数据隔离、失效粒度和私有数据。

**常见追问或变体：**不要将 cookie/header 派生的用户结果缓存为所有用户可复用的条目。

## 11. Node.js：事件循环延迟监控与 CPU 任务隔离

**参考答案：**记录 event loop delay 的分位数并和 CPU、GC、请求路径关联；CPU profile 找同步热点，必要时检查大量 Promise 回调。短小计算可优化或分片，重 CPU 任务放 Worker Thread；需要持久、限流、跨实例调度的任务放队列/独立 worker。为队列设置并发和长度上限、任务超时/取消与每租户隔离，避免把压力转移成无界排队。

**关键考点：**I/O 并发不等于 CPU 并发、诊断先于迁移、背压。

**常见追问或变体：**子进程隔离更强但 IPC/启动成本更高，适合不可信或需独立运行时的任务。

## 12. NestJS：CQRS 的适用边界与读模型一致性

**参考答案：**Command 表达改变状态的意图，Handler 负责校验和写入；Query 只读取，Event Handler 消费已发生事件更新读模型或触发异步动作。简单 CRUD 不必引入多套模型。异步读模型下，提交响应带 command/task id，前端先显示“处理中”并轮询/订阅状态，或对刚提交项乐观插入；记录 correlation id、事件版本、失败重试和死信，保证可观测、幂等的重放。

**关键考点：**读写模型分离不是强一致、最终一致 UX、事件幂等。

**常见追问或变体：**事件应表示已发生事实，不能把外部副作用的命令伪装成领域事件。

## 13. 接口设计：批量操作的部分成功、幂等与可恢复结果

**参考答案：**请求带客户端生成的 idempotency key 和稳定的目标项 id；500 项应返回 `202 Accepted` 与 task id，而非长连接等待。任务结果按目标项给 `status`、业务错误码、可重试标记和安全展示信息；服务端以幂等键关联同一任务，重复提交返回原任务。前端按退避轮询或订阅进度，刷新后用 task id 恢复页面；仅明确可重试的失败允许重新提交。

**关键考点：**HTTP 受理与最终结果分离、逐项结果、幂等持久化。

**常见追问或变体：**库存扣减还要以服务端原子操作保证，不可只依赖接口幂等键。

## 14. AI 前端：工具调用的“计划—确认—执行”交互

**参考答案：**把模型文本和工具意图视为不同状态：参数草稿只能预览；服务端根据 allowlist、schema、当前权限重新验证后生成带过期时间的 confirmation token；用户确认该 token 才能执行。确认页展示目标环境、影响范围、参数差异、所需权限、风险与到期时间。流式更新应使旧草稿失效，执行结果关联确认 id；模型不能自行把草稿状态跳为已执行。

**关键考点：**可信服务端状态机、确认绑定参数、过期和防重放。

**常见追问或变体：**高风险操作可要求二次认证或双人审批，而非只弹一个前端确认框。

## 15. Agent：上下文与工具链路的可观测性、脱敏和回放

**参考答案：**根 trace 关联会话、用户匿名标识、模型调用、检索、每次工具调用、审批和前端渲染事件；记录模型/提示版本、延迟、token、检索 chunk/version、工具结果摘要与错误分类。敏感输入、token、凭据和 PII 默认掩码或不落盘，按租户和角色控制原文访问并设保留期。回放使用已脱敏的输入、固定检索快照和工具录制响应；副作用工具替换为 mock，明确它是诊断模拟而不是再次执行。

**关键考点：**trace correlation、数据最小化、可重复且无副作用的回放。

**常见追问或变体：**采样不能漏掉错误和高风险操作；这些链路应强制全量审计。
