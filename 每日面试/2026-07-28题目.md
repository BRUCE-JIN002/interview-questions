# 2026-07-28 全栈偏前端每日面试题

## 1. JavaScript：`Set` 组合方法的集合语义与性能边界

- 题型：语言特性 + 场景设计
- 难度：中等
- 可能来源或考察方向：[MDN Set](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Set)
- 题目：权限页需要从“用户已拥有权限”和“当前角色允许权限”推导可见操作。如何用 `union`、`intersection`、`difference`、`symmetricDifference`、`isSubsetOf` 表达这几个集合关系？它们比较的是对象内容还是对象身份？当权限量达到数万、且来源数据是数组时，如何避免在渲染过程中重复构造集合？

## 2. TypeScript：模板字面量类型与类型安全的路由参数

- 题型：类型设计 + 手写
- 难度：较难
- 可能来源或考察方向：[TypeScript Template Literal Types](https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html)
- 题目：给定路由字面量 `'/teams/:teamId/members/:memberId'`，请设计类型 `Params<Path>`，推导为 `{ teamId: string; memberId: string }`；静态路径应得到 `{}`。实现时如何递归拆分路径？为什么该类型只适合字面量路由，不能代替运行时 URL 校验？如何防止路由规则过复杂导致类型计算拖慢编辑器？

## 3. Promise：`Promise.withResolvers()`、外部 resolve 与状态所有权

- 题型：原理 + 工程边界
- 难度：中等
- 可能来源或考察方向：[MDN Promise.withResolvers](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Promise/withResolvers)
- 题目：实现一个“等待 WebSocket 首次连接”的共享 Promise：连接成功时 resolve，关闭且未连接时 reject，超时后失败。`Promise.withResolvers()` 相比手写 `new Promise` 解决什么书写问题？为什么把 `resolve` 暴露给任意调用方会破坏状态所有权？多人同时 await 时如何复用同一 in-flight Promise，并在失败后允许下一次重连？

## 4. 浏览器：BFCache 命中、恢复与页面状态正确性

- 题型：浏览器原理 + 排障
- 难度：较难
- 可能来源或考察方向：[web.dev bfcache](https://web.dev/articles/bfcache)
- 题目：用户从订单列表进入详情再后退，偶发看到过期状态；团队又希望提高返回速度。BFCache 与 HTTP 缓存、SPA 内存缓存分别有什么不同？如何通过 `pageshow` 的 `persisted`、`pagehide` 以及 DevTools 判断页面是否从 BFCache 恢复？恢复后哪些数据应重新校验，哪些 UI 状态应保留？为什么不应在 `unload` 中做清理？

## 5. 网络：Client Hints、`Vary` 与响应变体缓存

- 题型：网络协议 + 性能设计
- 难度：较难
- 可能来源或考察方向：[MDN Client Hints](https://developer.mozilla.org/docs/Web/HTTP/Guides/Client_hints)
- 题目：图片服务希望按 DPR、视口宽度和 Save-Data 返回不同尺寸。服务端如何声明并消费 Client Hints？CDN 缓存键为何必须与 `Vary` 一致？`Vary: User-Agent` 为什么可能严重降低命中率？如果浏览器不发送 Hint，响应应怎样安全降级，并如何防止同一缓存条目误返回给不匹配设备？

## 6. React：`useOptimistic` 的回滚、确认与并发提交

- 题型：框架原理 + 场景设计
- 难度：较难
- 可能来源或考察方向：[React useOptimistic](https://react.dev/reference/react/useOptimistic)
- 题目：评论列表支持快速连续点赞。用 `useOptimistic` 设计“立即 +1、服务端确认后收敛、失败后回滚”的状态流；optimistic update function 为什么必须是纯函数？两次点击乱序返回、接口幂等重放、服务端返回权威计数时分别如何处理？什么时候应关闭按钮或把操作排队，而不是无条件乐观更新？

## 7. Vue 3：`watch` 的暂停/恢复、清理与异步竞态

- 题型：框架原理 + 排障
- 难度：中等
- 可能来源或考察方向：[Vue Watchers](https://vuejs.org/guide/essentials/watchers.html)
- 题目：筛选面板展开时监听多个条件拉取列表，收起后希望暂停请求，重新展开后恢复；请求返回顺序还可能颠倒。Vue 3 watcher handle 的 `pause`、`resume`、`stop` 分别适合什么生命周期？如何利用 watcher cleanup 取消旧请求？为什么不能只用一个 `loading` 布尔值解决竞态？

## 8. 手写：支持超时和取消等待的异步互斥锁

- 题型：手写实现 + 并发控制
- 难度：较难
- 可能来源或考察方向：综合整理
- 题目：实现 `createMutex()`，提供 `acquire({ signal, timeout })`，成功后返回 `release()`。锁空闲时立即获取；其余调用 FIFO 等待；超时或 signal abort 的等待者必须从队列删除；`release` 必须幂等且不能被错误调用两次后放行两个等待者。请说明为什么不能只用一个布尔值，以及在前端刷新 token、Node 单进程临界区中可如何使用它。
