# 2026-08-04 全栈偏前端每日面试题

## 1. JavaScript：`Error.cause` 与跨层错误语义

- 题型：JavaScript 原理 + 项目经验
- 难度：中等
- 可能来源或考察方向：[MDN Error cause](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Error/cause)
- 题目：前端请求层将 `fetch` 失败统一包装成 `ApiError`，但监控中丢失了底层 `TypeError`、HTTP 状态和业务错误码。如何用 `Error` 的 `cause` 设计错误分层，使 UI 能稳定展示、重试策略可判断、日志又能保留根因？哪些信息不应直接透传给用户？

## 2. TypeScript：`isolatedDeclarations` 与可发布类型声明

- 题型：TypeScript + 工程化
- 难度：较难
- 可能来源或考察方向：[TypeScript isolatedDeclarations](https://www.typescriptlang.org/tsconfig/isolatedDeclarations.html)
- 题目：一个组件库开启 `declaration` 和 `isolatedDeclarations` 后，部分导出报错，尤其是推断出的返回对象、匿名类型和跨文件常量。这个选项要解决什么构建问题？哪些公开 API 应显式标注类型，哪些地方不必为了通过检查而过度注解？如何避免实现细节意外进入 `.d.ts`？

## 3. Promise：批量异步操作的部分失败与结果契约

- 题型：Promise + 接口设计
- 难度：中等
- 可能来源或考察方向：[MDN Promise.allSettled](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Promise/allSettled)
- 题目：后台列表支持批量“重新发送邀请”，其中一部分可能因为权限、频率限制或网络失败而失败。何时应使用 `Promise.all`，何时使用 `Promise.allSettled`？请设计前端结果模型与 UI：如何展示成功/失败项、支持仅重试可重试项，并防止用户重复点击导致同一项并发提交？

## 4. 浏览器：Page Lifecycle 与离开页面时的数据保存

- 题型：浏览器生命周期 + 场景设计
- 难度：较难
- 可能来源或考察方向：[Chrome Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)
- 题目：富文本编辑器需要自动保存草稿。解释 `visibilitychange`、`pagehide`、`freeze`、`pageshow` 和 BFCache 的关系；为什么不能依赖 `unload` 发一个普通 `fetch`？请设计“本地立即持久化 + 后台同步”的方案，并说明恢复页面时怎样处理尚未上传、已过期或发生冲突的草稿。

## 5. 网络：幂等键与不确定写入结果

- 题型：网络协议 + 接口设计
- 难度：较难
- 可能来源或考察方向：[IETF Idempotency-Key Header](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/)、综合整理
- 题目：用户创建支付订单时客户端超时，但服务端可能已经成功落库。请设计 `POST /orders` 的幂等键协议：键由谁生成、服务端记录哪些请求指纹与结果、相同键但不同 payload 如何处理、响应重放多久、客户端重试边界是什么？它与“HTTP 方法天然幂等”有何区别？

## 6. React：复杂表单中的状态归属与派生状态

- 题型：React 状态设计 + 项目经验
- 难度：中等
- 可能来源或考察方向：[React Choosing the State Structure](https://react.dev/learn/choosing-the-state-structure)
- 题目：商品编辑页同时有服务端初始数据、用户草稿、字段校验、保存状态和“是否离开未保存”的提示。如何划分受控表单状态、派生状态和服务端状态，避免把 `isDirty`、格式化价格等可推导值重复存储？当路由参数切换到另一商品时，何时应重置，何时应提示用户？

## 7. Vue 3：`v-model` 多模型与组件 API 演进

- 题型：Vue 3 + 组件设计
- 难度：中等
- 可能来源或考察方向：[Vue Component v-model](https://vuejs.org/guide/components/v-model.html)
- 题目：设计一个范围筛选组件，同时支持 `v-model:start`、`v-model:end` 和 `v-model:timezone`。在 Vue 3.4+ 中如何用 `defineModel` 声明并约束这些模型？当开始时间晚于结束时间时，组件应直接改写另一个值、发出校验状态，还是拒绝提交？请从数据单向性、可预测性和兼容旧调用方说明取舍。

## 8. 手写：实现支持循环引用和内建类型的深拷贝

- 题型：手写实现 + JavaScript 基础
- 难度：较难
- 可能来源或考察方向：[MDN structuredClone](https://developer.mozilla.org/docs/Web/API/Window/structuredClone)、综合整理
- 题目：手写 `deepClone(value)`，至少支持普通对象、数组、`Date`、`RegExp`、`Map`、`Set`、循环引用和 Symbol 键；函数、DOM 节点、`WeakMap`/`WeakSet` 应如何处理？请给出核心 TypeScript 实现，并说明它与 `structuredClone`、`JSON.stringify` 的能力差异。

## 9. 算法：删除重叠区间的最少次数

- 题型：算法题 + 手写
- 难度：中等
- 可能来源或考察方向：[LeetCode 435](https://leetcode.com/problems/non-overlapping-intervals/)
- 题目：给定若干区间 `[start, end]`，删除最少区间，使剩余区间两两不重叠（端点相接不算重叠）。请给出贪心策略、证明为何优先保留结束时间最早的区间，并写出 TypeScript 实现；若区间改为闭区间，判断条件如何变化？

## 10. Next.js：路由级错误处理、恢复与观测

- 题型：Next.js + 可靠性设计
- 难度：中等
- 可能来源或考察方向：[Next.js Error Handling](https://nextjs.org/docs/app/getting-started/error-handling)
- 题目：App Router 的商品详情页由多个 Server Component 组成，某个推荐服务偶发超时。`error.tsx`、`global-error.tsx`、`notFound()` 分别适合处理什么？如何让 `reset()` 只重试可安全重试的读取、记录 request/correlation id，并避免错误页泄露内部异常或把用户刚输入的客户端状态全部丢失？

## 11. Node.js：CPU 密集任务的隔离与背压

- 题型：Node.js 性能 + 系统设计
- 难度：较难
- 可能来源或考察方向：[Node.js Worker Threads](https://nodejs.org/api/worker_threads.html)
- 题目：Node 服务要生成大批量图片缩略图和 PDF，事件循环延迟持续升高。为什么异步 I/O 不能解决 CPU 阻塞？请比较 Worker Threads、独立任务进程和外部队列消费者；设计一个有限 worker 池，说明如何限流、传递取消、处理 worker 崩溃和根据 event-loop lag/队列深度扩缩容。

## 12. NestJS：认证、授权与资源所有权的三层边界

- 题型：NestJS + 安全架构
- 难度：较难
- 可能来源或考察方向：[NestJS Authorization](https://docs.nestjs.com/security/authorization)
- 题目：管理后台的“编辑文章”接口既要验证登录，又要求角色为编辑或管理员，并要求编辑只能修改自己负责的栏目。请划分 Guard、参数/DTO 校验、Service 中资源级授权和数据库查询条件的职责；为何只在 Controller 写 `role === 'editor'` 不够？如何写集成测试覆盖越权、资源不存在和管理员例外？

## 13. 接口/数据库：乐观锁与冲突可恢复的编辑 API

- 题型：接口设计 + 数据库一致性
- 难度：较难
- 可能来源或考察方向：综合整理
- 题目：两名运营同时编辑同一篇活动文案。请设计基于 `version` 或 ETag 的更新接口，包括读取响应、更新请求前置条件、冲突响应体和前端合并流程；为什么不能简单“后写覆盖前写”？对自动保存、富文本字段与冲突审计，应分别增加哪些策略？

## 14. AI 前端：结构化生成 UI 的校验与降级

- 题型：AI 前端 + 场景设计
- 难度：较难
- 可能来源或考察方向：综合整理
- 题目：AI 助手会流式返回“文本说明 + 推荐组件树 JSON”，前端据此渲染表单、图表和操作卡片。如何定义受限 schema、在客户端和服务端分别校验、为组件和 props 建 allowlist，并在 JSON 不完整、字段非法或版本不匹配时安全降级为纯文本？为什么不能让模型直接输出任意 JSX/HTML 后执行？

## 15. Agent：任务预算、停止条件与可恢复执行

- 题型：Agent 开发 + 可观测性
- 难度：较难
- 可能来源或考察方向：综合整理
- 题目：一个数据分析 Agent 会检索知识库、调用 SQL 查询和生成报表，偶尔因工具反复失败而无限循环。请设计运行级预算与停止条件：token、步骤数、工具次数、耗时、花费和重复调用应怎样限制？失败后需要持久化哪些 checkpoint，用户如何选择“从检查点重试”“修改输入后新开运行”或“转人工”？
