# 2026-08-04 全栈偏前端每日面试参考答案

## 1. JavaScript：`Error.cause` 与跨层错误语义

### 参考答案

边界层把底层异常包装为带稳定 `code`、可安全展示 `message` 和 `cause` 的领域错误，例如 `new ApiError('NETWORK_FAILED', '网络异常，请重试', { cause: err })`。UI 按 code 决定提示与重试；日志递归记录 cause、request id 和状态码。令牌、SQL、内部栈和上游原始错误信息只进受控日志，不能展示给用户。

### 关键考点

错误分层、`cause`、稳定错误码、可观测性、信息脱敏。

### 常见追问或变体

不要为每层都重新 stringify 错误；保留原错误对象才有堆栈与分类价值。

## 2. TypeScript：`isolatedDeclarations` 与可发布类型声明

### 参考答案

它要求每个文件可独立生成声明，便于并行/增量的声明构建，也会暴露依赖跨文件推断的公开 API。导出的函数参数、返回值、类公开成员和复杂导出常应显式标注；局部实现无需处处注解。将内部辅助类型设为非导出，公开接口只暴露稳定 DTO，避免匿名推断把私有结构写进 `.d.ts`。

### 关键考点

声明生成、公开 API、类型边界、构建性能。

### 常见追问或变体

它不是运行时类型校验；组件库仍需做兼容性测试与语义化版本管理。

## 3. Promise：批量异步操作的部分失败与结果契约

### 参考答案

全成全败且任一失败应中止等待时用 `Promise.all`；每项结果都要展示时用 `allSettled`。前端把结果归一为 `{ id, status, retryable, code }`，成功项更新状态，失败项展示原因并只重试 `retryable` 项。提交前为每项建立 pending 状态或幂等键，禁用重复触发；服务端仍须保证重复请求安全。

### 关键考点

快速失败、全部结算、部分成功、重试分类、幂等。

### 常见追问或变体

`allSettled` 不会自动限并发；大量项目应结合任务池和取消策略。

## 4. 浏览器：Page Lifecycle 与离开页面时的数据保存

### 参考答案

`visibilitychange` 适合尽早保存，`pagehide` 可能进入 BFCache，`freeze` 前应停止可恢复工作，`pageshow` 需根据 `persisted` 恢复；`unload` 会妨碍 BFCache 且不可靠。编辑时先写 IndexedDB/本地草稿队列，再在可见或网络恢复时同步；离开时可用小型 `sendBeacon`/`keepalive` 补充，不把它作为唯一保障。恢复时按版本、更新时间和服务端 ETag 判断上传、提示冲突或丢弃过期草稿。

### 关键考点

页面生命周期、BFCache、本地优先、离线队列、冲突恢复。

### 常见追问或变体

`beforeunload` 只用于确有未保存风险的提示，常驻会降低 BFCache 命中率。

## 5. 网络：幂等键与不确定写入结果

### 参考答案

客户端为一次用户意图生成随机幂等键并在重试中复用。服务端按用户/租户加键保存 payload 哈希、处理中状态、最终响应和过期时间：同键同指纹返回原结果，同键不同指纹返回冲突，处理中可返回处理中状态或等待完成。客户端仅对可安全重放的网络/超时错误在预算内重试；`POST` 本身不天然幂等，协议赋予的是业务语义。

### 关键考点

不确定结果、请求指纹、响应重放、TTL、重试预算。

### 常见追问或变体

幂等记录应与业务落库尽量同事务，避免订单成功而键记录失败。

## 6. React：复杂表单中的状态归属与派生状态

### 参考答案

服务端数据由请求缓存管理；可编辑草稿用受控 state 或表单库保存。`isDirty` 由初始快照与草稿比较得出，格式化价格由原值派生，避免双写。路由切换时，未修改可按新 id 重置；有修改先给离开确认，确认后丢弃或保存草稿。提交成功后以服务端确认值替换快照和草稿。

### 关键考点

单一事实来源、派生状态、路由切换、未保存保护。

### 常见追问或变体

不要用 Effect 把每次 props 变化盲目复制到 state；那会覆盖用户输入。

## 7. Vue 3：`v-model` 多模型与组件 API 演进

### 参考答案

可分别声明 `defineModel<Date>('start')`、`defineModel<Date>('end')` 与时区模型，组件通过 emits 保持双向绑定契约。开始晚于结束时，默认更可预测的做法是发出校验状态并阻止父层提交，而非静默改写另一个字段；若产品规定自动修正，需明确事件和文档。保留旧的单一范围 props/emits 适配层并逐步迁移，不能无提示破坏调用方。

### 关键考点

多 `v-model`、`defineModel`、单向数据流、校验责任、兼容演进。

### 常见追问或变体

日期类型与时区序列化要统一，否则同一时刻可能在客户端和服务端比较出不同结果。

## 8. 手写：实现支持循环引用和内建类型的深拷贝

### 参考答案

用 `WeakMap` 记录已克隆对象，先登记再递归，防止循环。示例覆盖常见容器；真实业务优先 `structuredClone`，并明确不支持函数和 DOM。

```ts
function deepClone<T>(value: T, seen = new WeakMap<object, unknown>()): T {
  if (typeof value !== 'object' || value === null) return value;
  if (seen.has(value)) return seen.get(value) as T;
  if (value instanceof Date) return new Date(value) as T;
  if (value instanceof RegExp) return new RegExp(value.source, value.flags) as T;
  if (value instanceof Map) {
    const out = new Map(); seen.set(value, out);
    value.forEach((v, k) => out.set(deepClone(k, seen), deepClone(v, seen)));
    return out as T;
  }
  if (value instanceof Set) {
    const out = new Set(); seen.set(value, out);
    value.forEach((v) => out.add(deepClone(v, seen)));
    return out as T;
  }
  const out = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  seen.set(value, out);
  for (const key of Reflect.ownKeys(value)) {
    const desc = Object.getOwnPropertyDescriptor(value, key);
    if (desc && 'value' in desc) desc.value = deepClone(desc.value, seen);
    if (desc) Object.defineProperty(out, key, desc);
  }
  return out as T;
}
```

`JSON.stringify` 丢失 `undefined`、Symbol、Map/Set 和循环；`structuredClone` 支持更多可克隆值及 transfer，但同样不能克隆函数、DOM 和弱集合。

### 关键考点

循环引用、`WeakMap`、原型、属性描述符、可克隆边界。

### 常见追问或变体

`RegExp.lastIndex`、自定义类内部槽和访问器语义是否复制，应作为契约明确，而不是假设“万能深拷贝”。

## 9. 算法：删除重叠区间的最少次数

### 参考答案

按结束时间升序排序，扫描时若当前区间 `start < lastEnd` 则删除当前区间，否则保留并更新 `lastEnd`。保留结束最早者为后续留下最大空间，交换论证可证明任何保留较晚结束区间的最优解都可替换而不变差。

```ts
function eraseOverlapIntervals(intervals: number[][]): number {
  intervals.sort((a, b) => a[1] - b[1]);
  let removed = 0;
  let lastEnd = -Infinity;
  for (const [start, end] of intervals) {
    if (start < lastEnd) removed++;
    else lastEnd = end;
  }
  return removed;
}
```

时间 O(n log n)，空间取决于排序实现。闭区间端点相接也重叠时改为 `start <= lastEnd`。

### 关键考点

区间贪心、排序键、交换论证、边界条件。

### 常见追问或变体

若要返回保留集合，记录选中区间即可；若目标是最少会议室，改用堆而不是删除贪心。

## 10. Next.js：路由级错误处理、恢复与观测

### 参考答案

`error.tsx` 捕获所属路由段及其子树的渲染错误，`global-error.tsx` 用于根布局级兜底，`notFound()` 表示预期的资源不存在或按安全策略隐藏资源。`reset()` 只重试幂等读取；写操作应凭幂等键或明确恢复查询。服务端记录 correlation id 并在安全错误页给出该 id；客户端局部状态应放在未被错误边界替换的边界外或可恢复存储中，绝不展示原始堆栈。

### 关键考点

错误边界、404 语义、安全重试、关联日志、状态保留。

### 常见追问或变体

错误边界不能捕获事件处理器错误；事件处理器需自行处理并报告。

## 11. Node.js：CPU 密集任务的隔离与背压

### 参考答案

异步 I/O 只在等待 I/O 时让出事件循环，图片/PDF 编码仍占用 CPU。Worker Threads 适合进程内可控 CPU 任务，独立进程隔离更强，外部队列消费者适合长任务、独立伸缩和可靠重试。worker 池限制队列长度与并发，任务携带 `AbortSignal`/deadline，崩溃后拒绝或按幂等性重投；结合 event-loop lag、队列等待时间、CPU 和失败率扩缩容并设置熔断。

### 关键考点

事件循环、CPU 隔离、worker 池、背压、取消、容量指标。

### 常见追问或变体

大 Buffer 跨线程可用 Transferable 减少复制，但转移后原 ArrayBuffer 不可再使用。

## 12. NestJS：认证、授权与资源所有权的三层边界

### 参考答案

认证 Guard 解析可信身份；角色 Guard 做粗粒度角色门禁；DTO/Pipe 校验输入；Service 读取资源后判断栏目所有权，查询也带允许栏目条件作为纵深限制。只查角色不能知道该编辑是否有该资源权限。集成测试至少覆盖未登录 401、角色不足 403、同角色跨栏目 403/404 策略、资源不存在和管理员可编辑，并确认错误不泄露资源内容。

### 关键考点

认证、RBAC、资源级授权、DTO 校验、纵深防御、集成测试。

### 常见追问或变体

栏目权限频繁变化时需定义 session/缓存失效策略，不能无限相信旧 claims。

## 13. 接口/数据库：乐观锁与冲突可恢复的编辑 API

### 参考答案

读取返回 `version` 或 ETag；更新携带 `If-Match` 或版本号，数据库以 `WHERE id = ? AND version = ?` 更新并递增版本。未更新行数为零时返回 409/412 及当前安全快照、版本和可冲突字段，前端给用户比较、重载或逐字段合并。后写覆盖会静默丢失他人改动。自动保存应串行/合并同一文档更新，富文本优先 OT/CRDT 或明确段落级冲突策略，审计保存操作者、版本和差异。

### 关键考点

乐观锁、ETag、条件更新、冲突 UI、审计。

### 常见追问或变体

版本号是资源版本而非客户端时间；客户端时间不可作为并发先后依据。

## 14. AI 前端：结构化生成 UI 的校验与降级

### 参考答案

以版本化 JSON Schema/运行时 schema 定义有限组件类型和 props；服务端在模型输出后校验并过滤，客户端再次校验后才映射到受信组件。事件流未完成时只显示文本或加载态；非法字段、未知版本、校验失败则记录原因并降级纯文本/安全错误卡。任意 JSX/HTML 会扩大 XSS、数据外泄和任意行为面，模型输出必须是数据，不是可执行代码。

### 关键考点

结构化输出、双层校验、allowlist、版本化、XSS 降级。

### 常见追问或变体

即使组件在 allowlist，也要限制 URL、动作参数和数据访问权限，避免间接越权。

## 15. Agent：任务预算、停止条件与可恢复执行

### 参考答案

运行开始时设置 token、总步骤、单工具/总工具次数、deadline、成本和相同调用指纹上限；达到任一阈值即停止并输出可解释状态，而不是让模型自行决定无限重试。每个成功工具结果、已批准参数、检索版本、计划阶段、消耗和错误分类写 checkpoint。用户可从未完成的安全检查点重试，改输入则创建新 run 保留父 run 引用；不可恢复或高风险失败转人工并附审计摘要。

### 关键考点

预算、循环检测、checkpoint、幂等恢复、人工接管、审计。

### 常见追问或变体

恢复前要重新校验权限、工具可用性和数据版本，旧 checkpoint 不能自动继承已过期授权。
