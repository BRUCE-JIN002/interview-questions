# 2026-07-30 全栈偏前端每日面试参考答案

## 1. JavaScript：用 `WeakMap` 保存实例元数据的边界

### 参考答案

`WeakMap` 只接受对象键，键没有其他强引用时，键及其关联值可被 GC；普通 `Map` 会强持有键，SDK 很容易因缓存 DOM 节点造成泄漏。弱集合不可枚举，正是因为 GC 时机不可观测。需要批量释放时，SDK 应维护自己的订阅/控制器列表或显式 `dispose()`，不能依赖 GC；调试可在开发环境记录受控的诊断快照。

### 关键考点

弱引用、可达性、不可枚举性、显式资源释放。

### 常见追问或变体

值若从别处反向强引用键，仍会保活；`WeakMap` 不是“自动清理所有资源”的替代品。

## 2. TypeScript：`noUncheckedIndexedAccess` 与边界数据建模

### 参考答案

该选项把未声明索引访问视为可能缺失，避免缓存 miss 或越界读在运行时变成 `undefined` 后继续使用。缓存读应显式分支；必填配置在启动期用 schema 校验后转为没有索引签名的精确类型；数组应先判断长度或用 `at()` 后判空。按目录或包逐步开启，优先修复真实边界，不要把 `!` 当迁移工具。

### 关键考点

索引签名、undefined、运行时校验、渐进迁移。

### 常见追问或变体

`Record<K, V>` 在 `K` 是有限联合时可表达必填键；`string` 键不能承诺任意字符串都存在。

## 3. Promise：`Promise.race` 超时封装为什么常常泄漏工作

### 参考答案

`race` 只决定外层结果，超时并不会停止 `fetch`；胜出后未清除定时器会多留一个任务，未被观察的失败还可能形成未处理 rejection。包装层应创建/组合 `AbortController`：超时时 abort 并抛专用 `TimeoutError`，外部 signal abort 时抛 `AbortError`，其他错误原样或带 cause 抛出；结束时清 timer、移除监听。普通 Promise 没有统一取消协议，只有底层任务接受 signal 才能真正停止。

### 关键考点

竞速不等于取消、资源清理、取消原因、错误分类。

### 常见追问或变体

超时后的写请求可能已到达服务端，服务端仍需幂等键，不能把客户端 abort 当作事务未发生。

## 4. 浏览器：Popover API、top layer 与焦点管理

### 参考答案

`auto` popover 通常支持轻触外部关闭及同组互斥，`manual` 由应用控制；显示后进入 top layer，避免普通 `z-index` 竞争。`dialog` 的模态场景应使用 `showModal()`，它有阻止背景交互、焦点约束等语义，不能把普通菜单伪装成模态框。组件监听 `toggle`，把实际 `newState` 回写状态；`beforetoggle` 可在必要时阻止或准备内容。触发器、ESC、焦点回归和键盘导航要一并测试。

### 关键考点

top layer、声明式浮层、模态语义、状态同步、无障碍。

### 常见追问或变体

需要兼容旧浏览器时可降级为受控 portal，但仍要处理定位、焦点和点击外部逻辑。

## 5. 网络安全：Fetch Metadata 作为 CSRF 的纵深防御

### 参考答案

服务端可对非安全方法优先允许 `same-origin`/受控 `same-site`，拒绝明显 `cross-site`，并结合 `mode`、`dest` 限制不应从导航或嵌入发起的写请求。SameSite 降低 Cookie 自动携带，Origin/Referer 与 CSRF token 提供更精确的请求来源/意图证明；Fetch Metadata 是额外信号。缺失这些头的旧客户端、WebView 或明确允许的跨子域流程应走 token/Origin 校验的兼容路径，不能一概放行。

### 关键考点

CSRF、请求上下文、纵深防御、兼容性策略。

### 常见追问或变体

同站不等于同源；不可信子域存在时，`same-site` 也不能被默认视为安全。

## 6. React：`useImperativeHandle` 的最小命令式 API

### 参考答案

组件内部持有 input ref，只通过 `useImperativeHandle(ref, () => ({ openPicker, focus, clear }), deps)` 暴露少量命令；`clear` 同时同步受控值契约或请求父组件更新，而非私自改 state。不要泄露 DOM、AbortController 或上传队列，避免父级依赖内部实现。异步完成前检查挂载状态/当前任务 id，清理时 abort；命令应可安全地在严格模式重复挂载中创建。

### 关键考点

受控与命令式边界、稳定句柄、卸载清理、封装。

### 常见追问或变体

能用 props 和回调表达的状态不要改为 ref 命令；ref 适合 focus、滚动、打开原生选择器等命令。

## 7. Vue 3：泛型组件与具名插槽的类型契约

### 参考答案

列定义可用 `keyof T` 约束字段，行事件 payload 保持 `T`，组件通过泛型 SFC 或工厂函数连接这些类型；插槽参数声明为如 `{ row: T; column: Column<T> }`。这只约束编译期调用，接口返回仍是未知数据，须在边界做 schema 校验。若模板类型推断过重，可把列渲染抽为类型化 render 函数或收窄到公开的 `Row` DTO，优先保证可读性。

### 关键考点

泛型组件、`keyof`、插槽 props、类型与运行时边界。

### 常见追问或变体

不要为每个深层路径都构造复杂条件类型；复杂表格应把排序、过滤和权限能力拆成明确接口。

## 8. 手写：实现可取消的异步互斥锁

### 参考答案

维护 `locked` 和等待节点队列。获取锁时若空闲直接返回一次性 release；否则入队，并给 signal 加一次 abort 监听，取消时标记/移除节点并 reject。release 只能生效一次，跳过已取消节点后唤醒第一位有效等待者。

```ts
class Mutex {
  private locked = false;
  private queue: Array<{ grant: () => void; cancelled: boolean }> = [];

  acquire(signal?: AbortSignal): Promise<() => void> {
    if (signal?.aborted) return Promise.reject(signal.reason ?? new DOMException('Aborted', 'AbortError'));
    return new Promise((resolve, reject) => {
      let onAbort: (() => void) | undefined;
      const grant = () => {
        if (onAbort) signal?.removeEventListener('abort', onAbort);
        let released = false;
        resolve(() => {
          if (released) return;
          released = true;
          this.unlock();
        });
      };
      if (!this.locked) { this.locked = true; grant(); return; }
      const node = { grant, cancelled: false };
      this.queue.push(node);
      onAbort = () => {
        node.cancelled = true;
        this.queue = this.queue.filter((item) => item !== node);
        reject(signal.reason ?? new DOMException('Aborted', 'AbortError'));
      };
      signal?.addEventListener('abort', onAbort, { once: true });
    });
  }

  private unlock() {
    const next = this.queue.shift();
    if (next) next.grant(); else this.locked = false;
  }
}
```

入队/出队均为 O(1)，示例取消的 `filter` 为 O(n)，高频场景可用双向链表。持锁期间不应等待慢网络，避免队头阻塞。

### 关键考点

FIFO、幂等 release、取消清理、临界区最小化。

### 常见追问或变体

生产实现还要在 grant 后移除 abort listener，防止已获锁请求被随后 abort 重复 reject。

## 9. 算法：搜索旋转排序数组中的目标值

### 参考答案

每次中点至少落在一个有序半区。若左半有序，判断 target 是否在其闭区间内；否则搜索右半，右半有序时对称处理。

```ts
function search(nums: number[], target: number) {
  let left = 0, right = nums.length - 1;
  while (left <= right) {
    const mid = left + ((right - left) >> 1);
    if (nums[mid] === target) return mid;
    if (nums[left] <= nums[mid]) {
      if (nums[left] <= target && target < nums[mid]) right = mid - 1;
      else left = mid + 1;
    } else {
      if (nums[mid] < target && target <= nums[right]) left = mid + 1;
      else right = mid - 1;
    }
  }
  return -1;
}
```

时间 O(log n)，空间 O(1)。有重复时 `left`、`mid`、`right` 可能相等，无法判断有序半区，只能收缩边界，最坏 O(n)。

### 关键考点

二分不变量、旋转点、有序半区、重复值退化。

### 常见追问或变体

寻找最小值可用类似二分；不要把数组真的旋转回来，复杂度会变差。

## 10. Next.js：服务端 Data Access Layer 与页面级授权边界

### 参考答案

隐藏入口只是体验优化，直接 URL、Server Action、Route Handler 都可绕过。DAL 在服务端从 cookie/session 解析可信身份，按资源 id 查询并做权限判断，只返回页面需要的 DTO；三类调用者都经该函数，不能仅依赖 layout。用户身份/权限必须进入私有缓存键或禁用共享缓存，授权失败按场景返回 `notFound`、`forbidden` 或统一错误，不能把资源存在性泄露给无权用户。

### 关键考点

认证与授权、DAL、DTO、缓存隔离、资源枚举。

### 常见追问或变体

Middleware 适合粗粒度重定向，不替代数据层的资源级授权。

## 11. Node.js：慢请求（Slowloris）与 HTTP 服务资源上限

### 参考答案

`headersTimeout` 限制收到完整请求头的时间，`requestTimeout` 限制整个请求接收，`keepAliveTimeout` 限制空闲复用连接；具体默认值随 Node 版本核验。代理层先做连接/速率过滤，应用层限制 Content-Length 与实际流量、边读边处理并在超限时销毁请求。按真实网络分布设分阶段预算，观察 header/body 超时数、打开连接、请求大小、P95/P99 和地区/客户端，再调整，不能用极短一刀切值。

### 关键考点

慢速攻击、阶段性超时、流式限额、容量指标。

### 常见追问或变体

WebSocket 和 SSE 的超时模型不同，需 heartbeat、最大连接数和独立的资源配额。

## 12. NestJS：多租户请求上下文与 PostgreSQL Row-Level Security

### 参考答案

认证后从签名 session 得出 tenant，而不是信任 header；在每个事务内用参数化语句设置本事务局部 tenant 变量，RLS policy 用它限制 `tenant_id`。连接归还池前必须 reset，后台任务也要显式携带受审计的租户身份。RLS 是数据库兜底，应用层仍要验证用户对资源的操作权、限制跨租户管理操作，并用集成测试证明池复用和漏条件都不会越权。

### 关键考点

可信租户上下文、RLS、连接池隔离、纵深授权。

### 常见追问或变体

迁移账户的 `BYPASSRLS` 权限应极少授予；管理员跨租户查询需专门审计路径。

## 13. 接口/数据库：事务型 Outbox 的消费者去重与补偿

### 参考答案

业务数据和 Outbox 记录写在同一事务，避免“订单已提交但发布失败”或反向双写。发布器至少一次发送；消费者以 event id 建唯一幂等记录，在同一事务中执行副作用与标记，重复投递直接返回成功。通知成功但未确认 offset 时会重投，应由该幂等机制吞掉；乱序事件带聚合版本或状态机，仅接受可推进的版本，异常进入重试/死信并可人工补偿。

### 关键考点

原子写入、至少一次、消费者幂等、版本顺序、死信补偿。

### 常见追问或变体

Outbox 不等于端到端 exactly-once；外部不可幂等副作用仍需业务去重键或补偿方案。

## 14. AI 前端：流式事件的版本号、幂等合并与断线续传

### 参考答案

每个事件带稳定 `runId`、全局或 run 内唯一 `eventId`、单调 `seq`、类型和 schema 化 payload。reducer 按 `eventId` 去重，按 `seq` 拒绝旧状态覆盖，缺号时请求快照或从最后确认 seq 续传；文本可按 offset/序号追加，工具卡以 call id 合并。停止时客户端保留已展示内容、最后 seq 和用户发起取消的记录；服务端持久化 run 状态、取消原因、已执行工具及审计关联，避免重连后重复执行。

### 关键考点

事件幂等、顺序、断线恢复、状态机、审计。

### 常见追问或变体

最终摘要应是权威快照；客户端增量只是交互层，不能作为工具执行事实源。

## 15. Agent：高风险工具的策略引擎与确认绑定

### 参考答案

策略引擎在服务端、模型之外，对用户/租户权限、工具 allowlist、规范化参数、目标环境、数据敏感级别和风险规则做 allow、deny 或 require-confirm。确认页展示真实工具名、目标、变更 diff、影响范围、数据外发对象和可撤销性；确认后签发短时一次性票据，绑定 tool id、规范化参数哈希、用户、run 与 nonce。执行器再次校验票据，参数或目标改变即拒绝并重新确认，完整记录决策与结果。

### 关键考点

策略外置、最小权限、人类确认、参数绑定、审计。

### 常见追问或变体

批量删除应展示样本和总量阈值；超过阈值可强制二次确认或改为生成待审批计划。
